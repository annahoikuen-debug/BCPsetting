# フルオート・リッチWebtoonジェネレーター 実装計画書

## 1. プロジェクト概要
あらすじから、視覚的・聴覚的演出を伴う没入型の縦読みマンガ（Webtoon）を自動生成するプラットフォーム。
単なる画像の羅列ではなく、レイヤー合成、キャラクターの固定、スクロール連動アニメーション、音声生成を組み合わせた「体験型コンテンツ」を目指す。

## 2. 技術スタック
### バックエンド
- **言語/フレームワーク**: Python 3.11+ / FastAPI
- **LLM (頭脳)**: Gemini 1.5 Pro / Flash (シナリオ生成、プロンプト最適化、演出指示、画像評価)
- **画像生成 API**: Stable Diffusion API (Stable Diffusion XL) + Replicate InstantID / ControlNet。API キー未設定時は Pollinations.ai フォールバック
- **音声生成 API**: ElevenLabs (フルボイス) / VOICEVOX (ローカル実行)
- **BGM**: Suno/Udio API / プリセットライブラリ（API キー未設定時はライブラリからフォールバック）
- **画像処理**: Pillow (PIL), Rembg (背景除去)
- **データベース**: SQLite (開発) / PostgreSQL (本番移行予定)
- **ストレージ**: ローカルディスク (開発) / AWS S3 (本番移行予定)
- **非同期タスクキュー**: Celery + Redis
- **キャッシュ/進捗通知**: Redis (Pub/Sub + SSE)

### フロントエンド
- **フレームワーク**: Next.js (App Router), TypeScript
- **アニメーション**: Framer Motion, GSAP (スクロール連動演出)
- **状態管理**: Zustand / React Context
- **スタイリング**: Tailwind CSS
- **HTTPクライアント**: axios (+ TanStack Query)

## 3. データフロー
`あらすじ入力` 
$\rightarrow$ `LLM: シナリオ分解 (4コマ分) & 演出指示作成`
$\rightarrow$ `LLM: 各コマの画像プロンプト (背景/キャラ) 生成`
$\rightarrow$ `画像AI: 背景生成 $\rightarrow$ キャラ生成 (IP-Adapterで固定)`
$\rightarrow$ `画像処理: 背景除去 $\rightarrow$ レイヤー合成`
$\rightarrow$ `音声AI: セリフ音声化 $\rightarrow$ BGM生成`
$\rightarrow$ `フロントエンド: JSON形式の演出データに基づきリッチWebページとしてレンダリング`

## 4. 実装フェーズ (Phase 1 - 15)

### 【基盤構築フェーズ：MVPの実現】
- **Phase 1: 要件定義と環境構築**
  - APIキーの管理、ディレクトリ構造の決定、FastAPI/Next.jsのボイラープレート作成。
- **Phase 2: 基本的なシナリオ生成パイプライン**
  - Gemini APIを用いて「あらすじ $\rightarrow$ 4つのセリフ + 4つの場面描写」に分解する機能の実装。
- **Phase 3: 単一画像生成の統合**
  - 画像生成APIを連携し、場面描写から1枚の画像を生成し表示する基本フローの構築。
- **Phase 4: 縦読みビューアの基本実装**
  - Next.jsで画像を縦に並べ、その下にテキストを表示するシンプルなWebtoon形式のUI作成。
- **Phase 5: 非同期処理の導入 (Celery/Redis)**
  - 画像生成に時間がかかるため、リクエストを受けてから完了までを非同期で処理し、ポーリングまたはWebhookで通知する仕組みを構築。

### 【視覚的一貫性と品質向上フェーズ】
- **Phase 6: キャラクターの顔固定 (IP-Adapter導入)**
  - 1コマ目のキャラ画像をリファレンスとして以降のコマに適用し、同一人物として描写させる仕組みの実装。
  - **追加機能: キャラクターEmbeddingによる視覚的フィードバックループ**
    - Gemini Embedding API (`text-embedding-004`) を使用し、キャラクターの視覚的特徴をベクトル化。
    - 生成された「ベストショット」画像をVision APIで言語化し、Embeddingを更新するフィードバックループを構築。
    - `PromptBuilder` にEmbedding情報を注入し、生成ごとにキャラクターの外見がドリフトするのを防ぐ。
- **Phase 7: レイヤー別生成 (背景とキャラの分離)**
  - プロンプトを「背景のみ」「白背景のキャラクター」に分け、個別に生成するフローの実装。
- **Phase 8: 自動合成パイプライン**
  - Rembg等を用いてキャラの背景を透過し、Pillowで背景画像の上に合成するサーバーサイド処理の実装。
- **Phase 9: プロンプト・エンジニアリングの最適化**
  - LLMに「画像生成AIが理解しやすい形式」でプロンプトを出力させるためのシステムプロンプトの改善。

### 【演出と没入感の強化フェーズ】
- **Phase 10: スクロール連動アニメーション (基礎)**
  - Framer Motion / GSAPを用い、スクロールに合わせて画像がフェードイン・スライドインする演出の実装。
- **Phase 11: 演出指示データの構造化**
  - LLMに `{"effect": "shake", "timing": "scroll_pos_2"}` のような演出指示をJSONで出力させ、フロントエンドで解釈させる仕組みの構築。
- **Phase 12: 感情エフェクト・オーバーレイ**
  - 「悲しい $\rightarrow$ 雨」「激しい $\rightarrow$ 集中線」などの透過PNG/GIFをCSSレイヤーで重ねる機能の実装。
- **Phase 13: フルボイス生成の統合**
  - ElevenLabs APIを連携し、セリフに合わせた音声ファイルを生成し、コマ到達時に再生する機能の実装。
- **Phase 14: ダイナミックBGMの導入**
  - シーンの雰囲気に合わせたBGMを生成/選定し、バックグラウンドでループ再生させる仕組みの実装。

### 【最終調整とプラットフォーム化】
- **Phase 15: 全体最適化とデプロイ**
  - パフォーマンスチューニング（画像のWebP化、キャッシュ戦略）、UI/UXのブラッシュアップ、Vercel/AWSへのデプロイ。

## 5. 優先順位とマイルストーン
1. **Milestone 1 (Phase 1-5)**: 「あらすじから画像と文字が出る」最低限の機能完成。
2. **Milestone 2 (Phase 6-9)**: 「キャラが固定され、クオリティが高い」視覚的な完成度の向上。
3. **Milestone 3 (Phase 10-15)**: 「動いて、聞こえる」リッチな体験への昇華。
