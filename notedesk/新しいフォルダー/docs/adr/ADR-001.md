# ADR-001: 技術スタック選定

## ステータス
承認済み

## 日付
2026-10-29

## 背景
Rich Webtoon Generator は、あらすじから AI で 4 コマ縦読み Webtoon を自動生成するプラットフォーム。
プロトタイプ段階から MVP 開発を迅速に進めつつ、将来的なスケールアウトを見越した技術スタックを選定する必要がある。

## 決定事項

### バックエンド
| 項目 | 選定 | 理由 |
|------|------|------|
| 言語/フレームワーク | Python 3.11+ / FastAPI | 非同期処理に強く、型ヒントによる保守性、AI ライブラリとの親和性 |
| 非同期タスクキュー | Celery + Redis | 画像生成・音声生成など重い処理を非同期化。Redis は軽量で運用コストが低い |
| データベース | SQLite (開発) / PostgreSQL (本番) | 開発はファイルベースでセットアップ不要。本番は PostgreSQL へ移行予定 |
| ORM | SQLAlchemy (async) | 非同期 DB アクセスに対応。マイグレーションは Alembic を検討 |
| ストレージ | ローカルディスク (開発) / AWS S3 (本番) | 開発は簡易。本番は分散ワーカー間で画像を共有するため S3 へ移行 |
| 構造化ログ | structlog (JSON) | 構造化ログにより、ログ収集・分析が容易 |

### フロントエンド
| 項目 | 選定 | 理由 |
|------|------|------|
| フレームワーク | Next.js 14 (App Router) | SSR/SSG、App Router によるルーティング、React Server Components |
| 言語 | TypeScript | 型安全性によるバグ削減 |
| スタイリング | Tailwind CSS | ユーティリティファーストで迅速な UI 構築 |
| アニメーション | Framer Motion, GSAP | スクロール連動演出、Webtoon 特有のリッチな表現 |
| 状態管理 | Zustand, TanStack Query | 軽量な状態管理とサーバーキャッシュ |
| HTTP クライアント | axios | インターセプターによる StandardResponse 統一処理 |

### 外部 AI サービス
| 項目 | 選定 | 理由 |
|------|------|------|
| LLM (シナリオ/評価) | Gemini 1.5 Pro / Flash | 高品質な日本語出力、構造化出力 (response_schema) 対応 |
| 画像生成 | Stable Diffusion XL / Imagen / Pollinations.ai (フォールバック) | API キー未設定時でも動作するフォールバックを確保 |
| 音声生成 | ElevenLabs / VOICEVOX | フルボイス対応。VOICEVOX はローカル実行可能 |
| BGM | Suno/Udio API / プライズライブラリ | API キー未設定時は既存ライブラリからフォールバック |

## 代替案と比較

| 代替案 | 不採用の理由 |
|--------|-------------|
| Django | 非同期タスクと AI パイプラインとの相性が FastAPI に劣る |
| Nuxt.js | チームの React/Next.js 熟悉度が高く、学習コストを避ける |
| PostgreSQL からスタート | MVP 段階では SQLite で十分。本番移行は Alembic で対応 |
| S3 からスタート | 開発初期はローカルディスクで十分。ワーカー分散化時に S3 へ移行 |

## 結果
- 開発スピードを優先し、SQLite + ローカルストレージからスタート
- 本番環境では PostgreSQL + S3 へ移行することを想定
- `docs/adr/` に今後のアーキテクチャ決定を記録していく
